## Model and training

Same frozen DINOv2-registers ViT-B/14, bottleneck and eight decoder blocks;
no AMCM or paired synthetic denoising. Same-layer CLS is subtracted from patch
features before fusion; CLS/register prefix remains unchanged. This affects
bottleneck input, reconstruction targets and inference consistently; the
centered features are not fed back into encoder blocks. Grid shape derives
from token count (448/14=32); positional interpolation uses existing encoder.
V3 uses FP32 end to end. Encoder, recentering, reconstruction and loss stay in FP32; no encoder autocast is enabled.
No unconditional nan_to_num/clamp/retry is introduced.

Training-only horizontal/vertical flips each use probability .5. RRC uses
scale=(.85,1), ratio=(.99,1.01). Validation/test image transforms are deterministic
full-frame resize. Data manifests and normal-only filtering are unchanged.
Existing V0 hard mining already warms p from zero to .9 over 1000 steps.
Its easy-token gradient factor is .1 (attenuation, not literal token deletion).
Non-finite loss or gradients save sample paths, feature norm bounds, learning
rates, last completed gradient norm, tensors and recoverable failure checkpoint.
For a loss failure no current backward exists; last-completed gradient is labelled.

## Evaluation

One validation inference computes all z fractions (.001,.0025,.005,.01,.02,.05,.10).
Each checkpoint selects z by image AUROC, tie pixel AP. Across checkpoints
same rule; exact ties retain earliest checkpoint/first z. Both thresholds are
validation-only: normal score 90th percentile (NumPy linear interpolation,
>= comparison, empirical FPR reported) and maximum F1. Test never selects.
Historical 392-mask-to-256 main evaluation remains fixed independently of
448 image input. Supplemental 512 pixels use native512 masks, no image
operating-point claims at 512. Native-512 is run only after training by reevaluate_v3.py --native_512 and cannot affect training status. Both protocols must be compared with uniformly reevaluated
V0/V1/V2; changed input/training/evaluation is a bundled protocol, not an
isolated architectural gain. Gaussian and PRO implementation remain upstream.
Pixel prevalence is exported as AP random baseline. Bootstrap uses 2000
stratified image resamples with seed recorded; it does not estimate training
seed variation or bridge/session dependence. reevaluate_v3.py supports shared
protocol checkpoint evaluation and exact-path paired bootstrap delta to a
reference score CSV, rejecting missing/duplicate/mismatched identities.
Checkpoint must already be chosen by validation; helper does not search test.

## Limits and retention

Only AST, bytecode compilation, JSON and source checks have been run. Actual
runtime, GPU peak, numerical stability and performance are unverified. 448
memory estimates are not measurements. Retention compares against frozen V0
best_val checkpoints reevaluated with the same seven validation z candidates,
392-to-256 masks and threshold protocol. All four validation deltas (two datasets
x Image AUROC/Pixel AP) must be >= -0.005; at least one must be >= +0.01.
Test is reporting only. Paired bootstrap reference must use the reevaluated
V0 test_best_val_scores.csv with matching reevaluation.json provenance.

Review-approved execution order: V0 reevaluation on both datasets, then separate
50-step V3 smoke runs, then separately published full experiments. V3 smoke is
allowed, retains the 10000-step scheduler, uses a validation subset only for
pipeline checks, saves mode=smoke and experiment_result=false. V1/V2 smoke
restrictions remain. None of these stages is executed by this code publication.

Before a future launch, publish/verify commits and clean immutable worktrees
for both datasets and use the established shared GPU lock.
